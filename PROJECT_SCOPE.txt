Bar OS Starter – Project Scope / Reference

Overview
- Django app with multiple CMS modules (pages, events, shifts, POS, assets, merch, etc.) plus a minimal public site. Uses function-based views, Django templates, and DRF viewsets for the assets API.
- Entry points: CMS login at /accounts/login/, dashboard at /dashboard/, public landing at /. Core CMS layout in app/templates/cms/base_cms.html and nav in app/templates/cms/nav.html; public layout in app/templates/base_public.html.
- Common models: users.UserProfile/GroupMeta, setup.SiteSettings/opening hours/visibility rules (drives access control via guardian groups), assets collections/files (with per-group visibility), menu + merch + POS items, events + shifts scheduling.
- Dev: manage.py server; scripts/dev_windows.ps1 sets env. SQLite by default; can switch to Postgres via docker-compose db + DATABASE_URL.

Apps & Key Functions
- cms (app/cms/views.py): dashboard(request) renders CMS home; account(request) shows profile/account details.
- core (app/core/views.py): health(request) returns simple health check response.
- assets (app/assets/models.py, views.py): Tag, Collection (tree with allowed_groups, visibility_mode), Asset (file/url/text with visibility). Views handle index, toggle visibility, rename/update/delete for assets/collections, file serve. API (app/api/views.py) uses DRF ModelViewSets AssetViewSet/CollectionViewSet with filtering, ordering, and toggle_visibility actions; permissions checked via app.assets.selectors.user_allowed_for and guardian rules.
- setup (app/setup/models.py, views.py): SiteSettings (site metadata, hours flags), MembershipTier, OpeningHour, VisibilityRule (group-based access control). Views: setup_view renders settings; visibility_list/edit/delete/disabled/picker manage visibility rules; setup_access_required decorator gates access; ensure_hours_for populates default hours.
- pages (app/pages/models.py, views.py): Page model (title, slug, status, body_html, nav flags, visibility). Views: index() list; create/edit/delete via _handle_form helper; toggle_status publish/unpublish; preview renders draft; login_page_redirect checks if login page is mapped to a Page; _nav_builder_items builds nav entries.
- blog (app/blog/views.py): placeholder index/create/edit rendering templates with SAMPLE data.
- events (app/events/models.py, views.py): EventCategory, Event (with recurrence, doors, tickets, visibility/status flags), EventPerformer, EventRecurrenceException, HolidayWindow. Helpers (_add_months, _parse/_serialize_occurrence_param, _close_shifts_for_window, _compute_blackout_exceptions, _affected_recurring_events). Views: index filter/search events and occurrences; create/edit/detail/delete; edit/delete_occurrence handle recurring overrides; categories CRUD; holidays list/create/edit/delete holiday windows with shift/recurrence side effects (refresh_event_schedule, build_occurrence_series, sync_event_standard_shifts).
- shifts (app/shifts/models.py, views.py): ShiftTemplate, ShiftPreset(+slots), Shift, ShiftAssignment. Helpers _add_months and _build_index_context assemble calendar. Views: index calendar/list; assign assigns a user; create/update/delete_template manage templates; take allows self-assign; manage_event manages shifts tied to a specific event.
- pos (app/pos/models.py, views.py): DiscountReason, POSQuickButton, Sale/SaleItem, Payment. Helpers _money, cart helpers (_get_cart/_save_cart/_reprice_cart), variant labeling sizing helpers. API endpoints: api_search_items, api_browse_items, api_cart_add/remove/update/clear, api_quick_buttons, api_cart_apply_discount, api_cart_totals, api_checkout; uses ItemVariant from menu models.
- menu (app/menu/models.py, views.py): Unit/UnitGroup (measurement), Category (tree; root public/cms roots), Item (menu item with pricing, dietary flags), ItemVariant (size/price/quantity). Helpers _roots and _now; views manage_menu, items_list, category CRUD (create/edit/delete with optional parent/root), item CRUD; ties into POS items.
- merch (app/merch/models.py, views.py): Category, Product (visibility/status, price, variants), ProductImage, ProductVariant. CMS views for manage dashboard, category/product CRUD; public store views store_index, store_category, store_detail.
- bands (app/bands/models.py, views.py): Band with roster/links; views for index, edit (create/update), delete, public_detail.
- users (app/users/models.py, views.py): BadgeDefinition, FieldPolicy (profile field visibility rules), GroupMeta (group rank/role), UserProfile (avatar/bio/pronouns/badges/groups). Views include list/index, create_user, profile_detail/edit, badges CRUD, user_delete, group_hierarchy display, impersonation helper _can_impersonate; staff_or_super decorator helper; _group_rank/_top_group_for_user utilities.
- accounting (app/accounting/views.py), automation, door, inventory, maps, social: each currently has index/create/edit (or public detail) placeholder views and simple templates to scaffold sections.
- merch/pos/public assets: static files under app/static; templates per module under app/templates/<module>/; CMS/public base templates in app/templates/cms and app/templates/base_public.html plus public theme demos under app/static/publicthemes.

Notable glue
- Permissions: guardian object-level rules used in assets visibility and setup visibility rules; groups defined via auth + users.GroupMeta. VisibilityRule ties content types to groups/membership tiers.
- Scheduling: events recurrence utilities in app/events/scheduling.py (build_occurrence_series, refresh_event_schedule) and shift sync via app/shifts/services.py::sync_event_standard_shifts.
- SEO/branding: serving /robots.txt via template; django-robots installed (requires django.contrib.sites enabled). Setup form offers a favicon/manifest ZIP uploader that populates the “Site Icons” asset collection and auto wires favicon/apple-touch/manifest tags in base templates.
- Branding assets: Setup primary/secondary logos sync into the “Site Branding” assets collection for reuse across modules; uploading icons or logos replaces prior assets.
- API routing: DRF router likely configured under app/api/urls.py (noted assets viewsets); most other modules use Django template views with URLs per app/urls.py.

Getting around
- URL patterns summarized in PROJECT_METADATA.md (auto-generated) along with detailed model fields; use as exhaustive reference.
- Templates: CMS section pages live under app/templates/<module>/; public-facing pages under app/templates/public/ and app/templates/pages/.
- Static per module in app/static/<module>/ (e.g., cms.css, events.css, pos.js/pos.css, shifts.css).***

Jazzband packages to use/consider
- django-robots: manageable robots.txt for crawl control; currently serving a default template via /robots.txt with common disallows.
- django-recurrence: RRULE/EXRULE widgets + helpers to standardize event recurrence handling; Event now has recurrence_rule (RecurrenceField) with widget wired into forms.
- django-model-utils: AutoCreatedField/AutoLastModifiedField used on Event and Page; utilities available for broader status work.
- django-constance: DB-backed dynamic settings to complement SiteSettings.
- django-taggit: Generic tagging; if tags needed beyond assets.Tag.
- django-tables2 + django-filter: Table rendering + filter backends for CMS lists/DRF filtering.
- django-redis: Production cache backend; pairs with Celery/Redis already in stack.
- django-silk: Profiling when tuning performance.
- django-widget-tweaks (or django-floppyforms): Tighter template control over form rendering.
